# wallpaper-runner — 交付说明与验收记录

以本机桌面壁纸（Wallpaper Engine，2560×1600，像素风绿色小恐龙跑酷场景）为**唯一视觉基准**，
生成的**单文件、零输入、自动挂机**横版跑酷游戏。

## 一、怎么玩

**双击 `wallpaper-runner.html`** 即可（浏览器直接打开，无需服务器、无外部依赖）。

- 工作区根目录：`C:\Users\Lenovo\Desktop\deep seek\wallpaper-runner.html`
- 工程目录内同名副本：`wallpaper-runner\wallpaper-runner.html`

不需要任何键盘 / 鼠标 / 触摸输入：角色自动奔跑、自动跳跃 / 下蹲 / 变道，
撞到障碍物后显示本局金币与距离，停顿约 1.1 秒自动重开。

> 若用 DSH 预览面板打开，请用**绝对路径**；面板对相对路径的解析基准与工作区根目录不一致，
> 会报 `ENOENT ... wallpaper-runner\wallpaper-runner.html`（文件其实存在，是路径拼错了）。

## 二、验收结果

| 验收项 | 要求 | 实测 | 判定 |
| --- | --- | --- | --- |
| 单文件 HTML、无外部依赖 | 必须 | 63 KB，外部 `src/href` 引用 **0** 个 | ✅ |
| 稳定运行 5 分钟不崩 / 不白屏 | 必须 | 无头连跑 **1800 帧零异常** | ✅ |
| 自动重开流程 | 必须 | 死亡 → 面板 → 1.1s 后 `restart()`，已验证 | ✅ |
| 死亡次数 / 5 分钟 | ≤ 5 | **0.8**（5 seed × 300s） | ✅ |
| 单局平均存活 | ≥ 45 s | **233 s** | ✅ |
| 窗口自适应宽高比误差 | ≤ 1 % | **0.000 %**（7 种窗口尺寸实测） | ✅ |
| 逻辑耗时 / 帧 | < 16.7 ms | **0.44 ms** | ✅ |
| 视觉与壁纸同源 | 必须 | 逐层提取复刻，已肉眼比对截图 | ✅ |
| **金币收集率** | ≥ 70 % | **约 50 %** | ❌ **未达标** |

### 金币率为什么没到 70 %

金币分布在 3 条深度跑道上，而角色同一时刻只能站 1 条道 —— 单条道的理论上限是 33 %。
已做的改进（25 % → 50 %）：

1. 金币改成**多道同时铺设**（1~3 条道随机，并额外在角色前进道补一串），把理论上限抬到 ~62 %；
2. 金币高度从"拾取判定带的最边缘"移到**判定带中间**，拾取余量充足
   （单枚拾取单元测试：3 条道 × 9 种高度 + 4 种跳跃高度全部命中）；
3. 封顶 `COIN_MAX`，修掉了"同一个障碍物反复触发补币"导致的刷币（曾一度 5000 枚/局）。

再往上硬凑 70 %，只能把金币铺成"金币隧道"（每道每步都铺满），
那会明显破坏要求的**同源美术**观感。按你给的优先级
（稳定 > 安全 > 同源美术 > 金币收集率 > 性能上限），此处**取同源美术，放弃最后 20 个百分点**。

## 三、美术是怎么同源的

壁纸本身就是像素画，因此按"美术像素"逐层提取而非描摹：

| 层 | 提取方式 |
| --- | --- |
| 角色 | 从壁纸裁出 124×116 像素区块，按 4px 网格量化 → 37×34 美术像素精灵，保留原色（#8fa345 身体 / #fbe1b0 肚皮 / #feffed 眼白 / #b64b3c 舌） |
| 天空 | 沿无云列采样出 5 段色带 + y190–211 的棋盘抖动带（原图就有，做成一格 tile） |
| 月亮 | 圆心 (318,84)、半径 44 + 4 圈像素光环，位置与壁纸一致 |
| 云 | 从壁纸按色彩距离分割出 640×84 掩码（`tools/cloud_runs.json`），镜像平铺 + 120 列交叉淡化保证无缝 |
| 远山 / 中景山 / 针叶林 | 每 4px 采样轮廓线（`tools/layers.json`），等高分列合并成矩形绘制 |
| 粉色光束 | 上缘用实测轮廓、下缘用被暗峰切掉的斜线，还原壁纸那道月光 |
| 地面 | 程序化土壤纹（分层 + 碎石 + 草沿），取自壁纸土壤色板 |
| 障碍 / 金币 | 壁纸里没有可玩元素，按同源色板程序化生成（倒木 / 巨石 / 石柱 / 蝙蝠 / 金币），脚本 `tools/mksprites.py` |
| HUD | 右上角黄色 7 段数字（#fdf36a），复刻壁纸的 `00000 / HI 00029` |

## 五、关键不变量（改动务必保持）

1. 逻辑分辨率固定 **640×400**（壁纸 2560×1600 的 1/4），缩放与碰撞共用同一坐标系。
2. **美术、碰撞盒、AI 共用一条 lane 基准线**：`LANE_Y = [336,360,384]`、`LANE_STEP = 24`、
   `ART_FOOT = 8`、玩家 `footOffset = 0`、玩家碰撞盒 `[y-stand, y]`。
   （曾因三者错位 8px，表现为"隔壁道的障碍物把玩家撞死"。）
3. `obBox()` 把障碍碰撞盒**夹在自己 lane 带内**，避免伸进邻道。
4. 通行规则：地面障碍只能**跳过**；`bat` 是 `air`（跨所有道、统一高度 `FLY_Y1`）只能**蹲过**；
   `pillar` 无门，只能**换道**。
5. AI 用 `tryAction()` **前向模拟**（30 Hz、2.0 s 视野、道具向玩家移动）判定动作安全性，
   同一次模拟也数金币 → 优先级 **安全 > 金币 > 平滑**。
   - 跳跃候选额外留 3px 余量（真实 60Hz 与本模型有 1~2px 漂移）；
   - **变道途中横跨两条道，两条道都要做碰撞检查**（曾因此 2 秒速死）。
6. 生成 horizon（`scroll + AW + 560`）必须**大于** AI 视野，否则"障碍刚生成时 AI 看不到 → 早换道被撞"。
7. 金币只生成在**可达路径**上：平地 `foot-16`，跳障碍时按真实跳跃抛物线成弧。

## 七、已知未完成项

- **金币收集率约 50 %**（目标 70 %），原因与取舍见第二节。
- **浏览器实际帧率未实测**：无头 Chrome 在这台机器上起不来（`Multiple targets are not supported`），
  我改用软件光栅化 + DOM / Canvas 桩做了等价验证（逻辑 0.44 ms/帧、每帧约 730 次绘制调用）。
  游戏左下角挂了实时 FPS 读数，打开即可确认。
- 期间用无头模拟抓到并修掉的真实缺陷（都已验证）：
  `boot()` 从未被调用（页面是死的）、`s.x` 未初始化导致首帧崩、
  `CLOUD_RUNS` 在产物里被声明两次导致云层全空、针叶林 tile 画到画布外、
  金币刷币、变道途中的跨道碰撞。
